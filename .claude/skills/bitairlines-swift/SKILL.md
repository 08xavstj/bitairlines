# Swift conventions

## Layout

```
AirlineCore/            pure Swift package, Swift 6 strict. No UI, no Foundation, no system random or time.
  Sources/CoreSim/      SeededRandom, GeoMath (no libm), LinearTable, Powers
  Sources/CoreCatalog/  static data: Airport(+Data/ generated rows), Country, LandMask, AircraftType(+AircraftRows), StartRegions, PixelPalette
  Sources/CoreWorld/    the live game: World, Airline, Aircraft, Route, Demand, LegCost, Flights, Simulation, DailyUpdate, Issue, Progression, Tuning
BitAirlines/            the iPhone app, SwiftUI, landscape, Swift 5 language mode (on purpose: simpler for the local agent)
  App/                  entry, GameSession (clock, speeds, autosave), SaveStore (JSON files), AppSettings, Messages (the words)
  DesignSystem/         Theme, PixelFont (RingPixel), PixelUI (shapes, icons), PixelComponents, Components, Format, LogoSprite
  Art/                  AircraftSpriteData (GENERATED), Livery (role characters to colours), LogoTemplates
  Features/             Menu, NewGame (wizard, logo editor), Game (shell, map, fleet, routes, hangar, money, inbox, airline)
tools/                  data pipeline (build_data.py), art (art/), economy prototypes (sim/), local model helper, project generator
```

Dependency direction: `Features -> App -> DesignSystem/Art -> AirlineCore`. Core knows nothing about the app.

## Core rules (checked by `tools/check-core-purity.sh`)

1. No UI, persistence or platform imports. Foundation only in tests.
2. All randomness from the injected `SeededRandom`; draw order is part of the contract (add or reorder draws only with a `rulesVersion` bump).
3. Arithmetic only: `+ - * /`, `sqrt`, tables with linear interpolation. No `pow`, `exp`, `log`, `sin`, `cos`. Use `GeoMath.sine/cosine/arcSine`, `Powers.eighths`.
4. Value types, `Sendable`, `Codable`. A save is the `World` encoded as JSON.
5. No player-visible text in Core: emit codes and numbers; the app writes the words (`Messages.swift`).
6. Never decide by iterating a `Dictionary` or `Set` without sorting.
7. Every balance number lives in `Tuning.swift`.

## Working without a Mac (the author is on Windows)

- Push to `main`. The **Core** workflow (Linux) runs on every push: purity check and `swift test`. Read it: `git fetch origin ci-logs-core && git show origin/ci-logs-core:status.txt` then `core-test.log` (also has `CALIBRATION` lines).
- The **App** workflow (macOS) runs only when the commit message contains `[app]` or by hand. Read: branch `ci-logs-app`, files `app-test.log`, `generate.log`. On a private repo macOS minutes cost ten times as much, so batch app changes.
- On a Mac: `ruby tools/generate_xcodeproj.rb`, open `BitAirlines.xcodeproj`. The project is generated, never hand-edited, and not committed.
- Adding or removing an app source file needs no manual step: CI regenerates the project from the folders.

## Generated files (do not edit by hand)

- `CoreCatalog/Data/*.swift`: `python tools/build_data.py` (needs the raw downloads in `data/raw`, see `tools/README.md`).
- `BitAirlines/Art/AircraftSpriteData.swift`: `python tools/art/build_sprites.py`. Look at the art first with `python tools/art/preview.py`.
- The app icon: `python tools/make_icon.py`.

## App rules

- 8-bit look: text is always the pixel font via `.pixelFont(size)`; panels are `PixelShape` (stepped corners), never `RoundedRectangle` or `Capsule`; flat colours, no gradients; icons are 12 x 12 grids in `PixelIcon`; use the game's buttons and dialogs, not system alerts or SF Symbols.
- Aircraft are drawn from role characters (`Livery.colours`): the same rule is in `tools/art/preview.py`. Change both together.
- Keep files short (a few hundred lines) and views simple: one idea per file, helper views over long bodies.
- Game state changes go through `GameSession.perform { try $0.someWorldAction() }`; a refusal becomes a notice.
- Reduce Motion and the text-size steps are honoured (`Motion`, `pixelStep`).

## Gotchas found

- A shell `heredoc` with Swift code can fail to parse in the Windows bash tool; write files with the editor tool.
- Container jobs on GitHub default to `sh`; the Core workflow sets `shell: bash`.
- `xcodebuild` needs an `AppIcon` set when the target asks for one; `tools/make_icon.py` makes it.
- A function named `sin` or `cos` in Core trips the purity check (good: it protects against libm).
